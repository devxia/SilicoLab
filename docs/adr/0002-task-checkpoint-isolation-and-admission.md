# 任务执行检查点隔离与项目准入队列

已发布 pi-durable 1.4.0 的 `resume()`/submit/wait 会启动整个存储调度器，没有单任务暂停许可接口。为满足“暂停任务释放项目位置、新任务不带起其他未选择任务”，从 #11 开始，新的每个科研任务拥有项目内独立 `.silicolab/runs/<task-id>/session.sqlite`，项目主存储继续保存项目/对话/任务清单/固定输入/决定/产物来源与队列。项目调度器同一时刻只驱动一个任务的真实 pi-durable 循环，不修改第三方调度器、不嵌套第二个 agent 框架或让 Python 接管模型循环。

选择此布局而不是伪造暂停、永久 abort 后重建对话，或让全局resume唤醒所有旧任务。代价是更多存储文件，应用需在对话视图聚合真实历史；独立运行存储与任务UUID绑定，多个存储均由同一个项目owner持有，不允许并发第二写入者。缓存最多8个运行存储，活动存储不淘汰，其余关闭后可被只读重开；关闭不授权执行。

队列按持久入队顺序选择已授权 ready 项。等待用户或暂停不主动执行；答复明确继续和恢复动作按当前尾部重新入队，准入前重新核对固定输入/完成产物/内核阻塞。等待、排队、执行和暂停分别记录，启动只重建待恢复清单，不自动驱动原队列。

先前项目主库中的历史执行继续用原身份读取，暂停的旧执行只在明确选择时使用原内核恢复，不能为迁移重算或改写已完成来源。新任务模型/工具通过实际运行存储的 ExecutionOwner + submission/requestId 绑定应用任务，不按目标文本、最近任务或页面选择推断归属。

当前资源上限为4个打开项目host、每项目1项主动任务、100项未完成任务以及8个缓存运行存储；有实际2项目并行/3任务串行和容量拒绝证据，不代表无限并发或任意硬件吞吐保证。原生分发与备份/升级需覆盖整个 `.silicolab/` 项目内容，不可只复制主SQLite。
