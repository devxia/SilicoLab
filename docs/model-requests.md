# 对话模型切换、请求用量与有限重试

对应 [Issue #15](https://github.com/devxia/SilicoLab/issues/15)。仅用人工文本、蛋白序列与回环 Responses/Messages 端点验收；实际 provider 兼容性仍归 #22。

## 请求边界而非任务绑定

当前对话的配置UUID是下一次实际模型HTTP请求的选择。切换不暂停当前请求，不打断已授权工具；新选择在下一请求（包括明确的重试请求）取得必要历史。UI 同时显示在途实际来源和待生效选择；切换本身构成新接收方使用必要历史/已授权内容的许可，不重复确认，也不赋予新的工具/科学上传权限。

pi-durable 仍是唯一模型/工具主循环。内核使用应用注册的请求分派provider；每次调用分派器先读取对话当前配置、解析自己的安全凭据，再调用对应pi-ai标准adapter。分派器不是第二个agent loop，只包装一次模型请求和至多三次有限传输尝试；SDK与内核通用重试均关闭，避免重试相乘。在途请求解析后固定其来源，不因下拉选择更新而改发另一地址，不自动跨模型回退。

项目不绑定provider，任务不把创建时模型作为之后请求的接收方保证。按请求保存实际配置UUID、provider、协议、endpoint、model。任务旧字段仅保留初始选择用于历史兼容；追溯以 `task.modelRequests` 为准。

## 历史与科学效果

新任务检查点继续采用ADR0002的隔离存储。请求分派器通过现有借用机制读取同一对话较早任务的持久模型历史，与当前任务上下文一起交标准adapter跨协议转换，不截断工具结果或删除旧提示以伪装兼容。必要历史超过1,000,000字符时明确停放而非静默丢弃；服务拒绝上下文/工具协议则保存错误，保留原始记录。

模型重试不会执行工具，只有内核接受完整终态toolUse才进入工具循环。本地D2P任务固定输入及参数，已有完成执行在同任务后续模型重复请求时先核对已登记产物哈希并复用，不再次科学计算；既有DNA和产物目录不覆盖。暂停/恢复也继续核对完成项。所有受控工具还以工具名、完整参数、固定输入版本及科学参数的SHA-256指纹匹配已完成项，恢复后的新内核工具身份也可复用；不以截断的展示输入匹配，不同完整参数仍独立执行。

## 用量不虚构零

`task.modelRequests[]` 每次实际尝试先登记running，返回后保存completed/error/cancelled、时间、递增attempt、请求参数、取消/错误与retryAt。对话 `modelRequests` 数量统计实际调用尝试，包括本机验证；历史任务/对话可检视每个实际接收方。

原始协议事件只有明确给出的token值才记账；input/output/cacheRead/cacheWrite缺失用null表示未知。模型价格未配置时cost=null，界面显示未知，不用pi-ai默认的零费率做费用结论。错误请求可能已产生费用，缺少usage也仍是未知。UI按任务展示请求列表，在对话历史中可追溯，不按预算或费用阈值暂停。

## 有限重试与恢复

- 可重试：HTTP429、临时5xx/网络错误、已见协议起始后断流。至多3次尝试，退避100ms、200ms，有明确日志记录和可取消的等待。
- 不可自动重试：认证401/403、未配置/已移除、未见兼容协议的无效流或上下文问题。立即停放并提示，不换接收方。
- 连续失败保存paused及来源/用量/完成工具，释放项目执行位置；用户明确恢复在原任务隔离库中建立新恢复提交，不复用已终结的旧submission。保留原历史、尝试与完成产物。
- 用户取消的在途请求记录cancelled，不退避重试；宿主中断的running记录重开标interrupted，用量缺失仍未知，不假称未调用或零费用。重开不自动恢复；若恢复提交已持久完成而应用清单结算丢失，重开按当前有效恢复requestId对账已完成结果，不误用原失败提交。

本机失败重试与科学远端效果未知是不同契约：不会把模型网络重试许可当作ProteinFactory科学请求重提许可。科学远端仍遵守 #13 的先核对/明确决定。
