# 项目目录离线、重新定位与移除关联

对应 [Issue #19](https://github.com/devxia/SilicoLab/issues/19)。只对临时人工项目做移动、不可写和断开故障注入，不删除私人目录。

## 目录可用性是执行前提

Python项目宿主与Node运行时分别固定项目目录、`.silicolab`及主SQLite的device/inode，拒绝符号链接替换和身份变化，检查可读写及写入mode。两侧75ms监视，不以保持打开的SQLite句柄当作目录仍可用；每次应用操作、模型请求、工具开始和项目文件写入/目录创建前重新检查。Node失去目录时停止进程，应用监督器回收科学worker；Python监视器停止并回收对应Node/科学进程，不尝试将新状态flush到已移动或替换的路径。其他项目宿主独立继续。

该守卫是存储可用性保护，不是脚本沙箱，也不声称消除文件系统TOCTOU、故障瞬间的既有内核写入、网络已发生效果或任意存储故障。不能访问或写入的目录不自动创建替代项目，不改存应用数据目录。未知远端效果仍遵守原请求/科学对账契约。

应用在内存保留最近成功观察的项目快照；离线响应为 `availability.status=offline`、`progressSaved=false`、具体原因。快照中的运行/排队项显示暂停待核对，**不代表此改状态已落盘**。UI明确“只显示最后已观察状态；最新进度未确认保存”，不能把旧草稿/流式进度当作已保存。离线操作返回错误，SSE只观察/报问题不重新执行；500ms应用状态观察使打开的界面显示离线原因。已有索引项即使路径缺失也可选中查看离线状态及重新定位入口。

## 明确重新定位

POST `/api/workbench/projects/<id>/relocate` 使用用户所选存在目录。先停止原受管宿主，再以期望项目UUID打开：主项目身份在恢复对账前核对，不接受同名空目录或另一项目。然后验证所有固定输入版本及已登记产物的实际内容/哈希；失败不更新应用索引，不启动任务，不在空目录创建`.silicolab`。

所有打开和创建入口在关联发布前无条件共用此完整性核验（包括移除关联后重新创建已有项目），不因未传expected_id而绕过。普通打开先读取候选UUID（不运行任务），释放路径锁后加入实际UUID的项目生命周期锁，再核验与发布；当前原目录仍在线时拒绝另一份同身份副本冒充重新定位。验证通过后原项目UUID与新路径关联；保留原对话、输入版本、任务、请求、检查点、来源及产物。旧运行状态重开时按内核对账，未完成项仍暂停，**用户逐项选择恢复**，不因目录重新可用而自动发请求。恢复继续核对输入与完成产物。离线/移动前已发生的科学外部效果不因重新定位而视为撤销或允许重提。

前端按项目/对话在内存保留未保存草稿及保存状态（包括空字符串修改），切换到其他项目再返回不覆盖；重新定位核对后沿用草稿文本和磁盘实际revision，用户再明确保存。不声称离线期间保存成功；浏览器关闭/刷新前尚未落盘的内存草稿仍不是已保存数据。侧栏切换以及打开/创建其他项目的目录弹窗都不要求离线项目先保存无法保存的草稿；离线新建当前项目对话仍拒绝。目录原件由用户选择，不执行删除或自动迁移内容。

## 移除不是删除目录

DELETE `/api/workbench/projects/<id>` 只修改应用 `projects.json` 关联，正常关闭该宿主，不删除项目目录及文件。

- running、queued、admission_pending或提交中的活动必须先由用户明确暂停/取消；移除请求先拒绝，不替用户隐式处置。
- 离线项目先重新定位核对再移除；不能用移除抹去未知状态。
- 已暂停、等待用户或外部结果等持久状态保留。移除不取消独立外部作业，不代表服务端撤销。
- 再次打开原目录找回相同UUID/对话/任务/产物。应用索引原子替换、权限0600；候选索引成功落盘后才发布内存关联，失败回收新临时宿主并保持原关联。目录及科研内容保留。

## 生命周期并发

任务准入、观察、重新定位与移除使用同一项目级操作锁；旧观察的离线发布还核对当前宿主身份，不能在成功重新定位后写回旧离线状态。路径锁防止同目录出现多个宿主，四宿主上限包括正在核验的保留位置。内容读取/哈希和宿主关闭不占全局索引锁，仅索引发布阶段短暂持有全局锁；一个项目重新定位的大量核验不阻止其他项目状态/准入。

## 验证

```bash
npm --prefix runtime run typecheck
npm --prefix runtime test
.venv/bin/python -B -m unittest discover -s backend/tests -p test_project_availability.py -v
npm --prefix frontend run build
.venv/bin/python -B tests/e2e/fixtures/workbench_fixture.py
.venv/bin/python -B tests/e2e/browser_workbench_availability.py
```

9项应用契约覆盖真实移动/只读/断开、在途人工模型被停止且无后续请求、另一项目实际工具正常执行、同名空目录/另一UUID/篡改固定输入拒绝（含普通打开和创建已有项目入口）、明确重新定位后逐项恢复、已保存草稿不被失败覆盖，以及活动移除拒绝/暂停后仅取消关联/重开找回；并发屏障覆盖旧离线观察与重新定位、移除检查与新任务准入、耗时核验与另项目操作，以及索引替换失败时内存/磁盘关联一致。浏览器通过真实移动显示离线、刷新后保持离线入口、空目录拒绝、重新定位、草稿/任务/产物字节一致、移除后目录保留并重开同身份。运行输出位于忽略的 `outputs/ui/project-availability/`。

本项不声称网络文件系统、突然断电或任意I/O故障零数据损失；磁盘不可访问时明确无法确认最新保存，恢复以重新可读的真实记录和内容核验为准。
