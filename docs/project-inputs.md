# 项目文件与固定输入契约

对应任务 #5。项目文件通过浏览器原生文件选择器读取用户选定字节，再通过本机应用契约送至真实 Node 宿主；不读取父目录或保留长期外部原件引用。单文件最多 5 MiB，同名文件用独立 UUID 路径保存，原件不覆盖。

## 持久内容

- 导入副本：`<项目>/.silicolab/files/<id>-<name>`，由用户在项目内维护，允许以后编辑。
- 固定副本：`<项目>/.silicolab/inputs/<input-version-id>/<file-id>.bin`，在任务使用前固定实际字节；读取时核对 SHA-256 和长度，不把仍可变的导入副本当作固定来源。
- 元数据：pi-durable 项目文档保存文件名、项目相对来源、版本号、哈希、长度和固定时间。固定记录的身份与对话、科研任务、内核 task ID 不混用；固定输入不会提交模型、创建执行任务或标记科学计算完成，后续执行任务引用此记录。

新文件或固定副本先以独占创建、写入并 sync，随后才提交元数据；写入或持久化异常不报告成功。失败可能留下没有引用的本机文件，不向用户呈现为已固定，不能用自动清空整个项目来回收。文件读取有大小限制，拒绝符号链接和非普通文件；冻结前后读取状态有变化时拒绝并要求重试。存储故障/断电不承诺零丢失。

固定后的任务输入按已提交字节使用，不受以后原件/导入副本修改影响；下一次固定读取新的导入内容，增加版本号。用户直接改写固定文件会触发完整性错误而不是静默使用新内容。多个文件的固定版本是一个完整元数据提交，不在部分保存后标记成功。

## 应用 interface

均在本机 `/api/workbench/projects/<project-id>` 下，沿用项目身份核验与单一宿主所有权。

| 操作 | 契约 |
|---|---|
| POST `files` | `name`、`contentBase64`；成功后返回 id、路径、长度、原始导入哈希与时间 |
| GET `files/<file-id>` | 当前项目副本的 UTF-8 预览或二进制标记；前 8000 字节，明确截断；不以预览替代完整输入 |
| POST `input-versions` | 对话身份和 1–20 个不同 fileIds；提交固定记录，返回固定输入内容、版本与哈希 |
| GET `input-versions/<id>` | 校验后返回完整固定字节（base64）、项目相对来源、版本与长度；不存在或损坏明确失败 |
| GET 项目 | 返回已持久保存文件和输入版本清单，不扫描外部目录 |

界面文件区提供真实导入、选择、预览、固定与历史版本比较；保存期间禁用重复动作、错误可见，不凭页面状态声称落盘。目录/标记/文件名不能授予额外权限。文件内容不会自动发送给任何模型或科学服务。
