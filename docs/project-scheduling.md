# 项目队列、并行与恢复选择

对应 #11，技术布局见 [ADR 0002](adr/0002-task-checkpoint-isolation-and-admission.md)。项目内按持久 FIFO 同时主动执行一项；不同项目使用不同 Node owner、状态和输入，可并行。Python 应用的索引锁不跨项目持有长 IPC，任务计算也不依附页面连接。

## 准入规则

- 新任务保存稳定身份与原授权，缺少决定先 needs_decision，不占执行位置；范围内 ready 项保存为 queued 并排入项目队列，当前空闲才准入。
- active 仅一个，内核实际完成/失败并保存来源后释放位置，按顺序驱动下一 ready 项。入场检查失败时该项保存 paused 与原因，保留原输入/产物，后续合格项仍可执行，不被坏输入永久卡住。
- 用户答复只保存决定，明确继续动作把该任务放到当前队尾；暂停实际停止运行并释放位置，已排队任务继续；恢复请求也重新排到队尾，不插队、不绕过串行。
- 任务的运行存储隔离，暂停 A 的检查点不会被 B 的 submit/wait/resume 顺带启动；同一人类对话中的多个任务也不共享运行调度许可。输入、输出、内核submission/工具身份由 ExecutionOwner 绑定到具体任务。
- 新任务入场、运行中模型参数改变和状态观察是不同操作；本切片不把模型选择当作任务提交。真实模型切换在 #15 接入，不因此引入额外队列项。
- 宿主重开时保留队列身份及原顺序记录，原 queued/running 项变为 paused 待选择，不自动驱动；用户明确选择项重新按当前队尾准入，不把整个项目一次性恢复。
- 未来独立外部作业由 #12 的模拟执行器接入，沿用“等待状态不占主动位置、结果到达按继续条件重新入队”的准入契约，不能把本地在途脚本当作独立外部作业。

## 有界资源

当前最多4个打开项目host，每项目1项主动工作，因此上界4个项目主动任务；每项目最多100个未完成任务。第5个项目打开会明确拒绝，且不创建该项目状态；后续项目移除/关闭流程会增加释放入口，当前可完全退出后重新选定目录。

每项目缓存最多8个运行存储，正在执行的存储保护不淘汰；打开/初始化/淘汰/关闭沿单一异步操作线串行，非活动历史读取只能在有作用域的借用操作内完成，避免异步cache miss创建第二宿主或在读取中被关闭。初始化身份/根记录失败后关闭新宿主，不留未登记句柄。其他只读/暂停/完成存储关闭后按需重开，关闭缓存不等于取消或恢复任务。原始科研数据仍全部归属项目目录，无全局科学结果副本。此上限是当前可核验资源约束，不声称任意模型、计算规模或设备达到相同性能。

## 状态与界面

对话/任务面板明确显示已排队、正在执行、等待决定、已答复待明确继续、已暂停与实际错误；允许运行期间安排下一个目标。运行目标按入队记录执行，刷新只读历史和当前进度，不改变队列或产生重复执行。多个运行存储的 transcript 按真实时间聚合，人类对话仍是同一项目记录。

外部等待、暂停和用户决定各自有独立语义；不以更改视图标签替代实际回收，不以资源上限或排队规则改造成费用预算。
