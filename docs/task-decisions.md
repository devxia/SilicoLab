# 持久化的任务决定

对应 #9。需要用户判断时，任务保存为 `needs_decision`，问题/选项/答复和固定输入归属同一任务。等待不启动模型、工具或计算，不反复生成同一个问题；内核仍是唯一 agent 循环。

## 两类明确决定

- **终止符**：D2P 本地专项可以选 `stopPolicy=ask`（任务表单默认），可信 Python 入口仅检查固定 FASTA 是否有缺失终止符，不运行编码算法。缺失时保存 `terminal_stop` 问题，选项为保留原输入或仅为本任务补充末尾 `*`。无缺失时沿用 preserve，不伪造必须回答的问题。已有明确 preserve/add 选择不重复询问。
- **工具授权**：所需受控工具未授权时保存 `tool_authorization` 问题，选项为仅授权本任务并继续，或不授权并取消。它不能授权任意 shell、其他未知工具或科学远端；工具集合仍由任务模式和已有明确专项许可约束。

用户在对话或任务面板选择选项；结果记录实际答复和时间。最终答复先持久为 `admission_pending`，再由该次用户操作明确调用 `/tasks/<task>/continue` 进入内核。若继续请求失败或进程在两步间退出，界面保留“继续已答复任务”；启动、重复答复本身不自动提交。终止符选择写入任务参数，不改写项目导入副本或已有固定字节。模型文字、未知选项和别的任务/问题身份不能替代用户决定。

有多个必要问题时保留各自稳定 UUID，全部答复前不执行；拒绝授权立即取消该任务，不增加模型请求。等待记录可在正常关闭、Node SIGKILL 后重开，问题身份/选项不变且调度器暂停；只有用户明确答复才继续。

## 幂等与继续条件

POST `/api/workbench/projects/<project>/tasks/<task>/decisions/<question>`，正文 `{ "answer": "<option-value>" }`。只接受保存选项。相同答复返回已保存状态，不再次推进；不同答复不能覆盖已经回答的问题。问题不存在、任务不等待、项目身份不符或继续条件未满足时拒绝并明确报错。

答复最后一个问题前及显式继续时核对固定输入完整性与项目当前执行状态。继续先按同一对话/requestId 查询已存在内核提交，只创建缺失工作，并持久关联 submissionId；已有提交复用，重复继续不重做工具。模型与工具根据实际已准入 submission 的对话/requestId 查找任务；不按同一对话中“最近的任务”猜测，多个已答复待继续项也不会串用输入或授权。当前切片在项目已有内核提交时要求稍后继续，不借答复带起待恢复工作；#11 将扩展项目排队规则。等待任务没有内核输入提交，不占用主动执行位置。

任务入场的 requestId 目标/输入/参数/原授权另作 admission 记录；答复后的任务参数与授权可以改变，但重复发送原 requestId 仍识别同一任务，不能因此创建第二个问题或执行。已保存的 preflight 结果和固定输入版本复用；答复不重复导入、固定输入或执行已完成科学步骤。

用户答复是对该任务继续的明确操作，不等于应用启动自动恢复。当前未完成执行步骤、暂停/系统退出恢复由 #10 及后续生命周期任务验收；不宣称任意存储故障或进程崩溃窗口零丢失。

```bash
npm --prefix runtime run typecheck

```

真实任务从无终止符 MK 固定输入触发问题，等待模型计数0；SIGKILL Node、当前应用内重开、整个应用重开后问题仍一致。还在最终答复已提交、内核尚未准入的确定窗口 SIGKILL，验证重开与重复答复仍为零模型请求，显式继续及重复继续只执行一次。选择 add 只在任务使用 MK*，导入副本和固定字节不变。多问题/工具授权同意与拒绝、重复/冲突/非法答复、重复原请求不创建新执行均有应用契约断言。同一对话先保存 A/B 两个不同固定输入的答复，明确先继续旧任务 A 时只使用 A 输入/产物归属、B 保持未执行，再继续 B 只用 B 输入，也有真实执行回归。浏览器从对话和任务面板答复、刷新保留问题及任务身份、拒绝后模型调用数不增也通过；模拟继续HTTP失败后，持久答复保留、刷新可明确重试且不自动执行；不使用真实认证或外部服务。
